# 执行算法与做市策略

> 一句话：好信号也需要好执行——大额订单若一次性下单会冲击价格，执行算法负责把「要不要买」和「怎么买」分开，把冲击成本降到最低。

## 1. 为什么需要执行算法

- 大额订单直接吃掉盘口挂单会造成显著滑点（冲击成本）  
- 执行目标：在**成本、速度、隐蔽性**之间取得平衡  
- 对个人投资者：小资金冲击有限，但理解执行逻辑有助于理解「为什么大资金进出会影响短期价格」  

## 2. 主流执行算法

| 算法 | 全称 | 逻辑 | 适用场景 |
|------|------|------|----------|
| TWAP | Time-Weighted Average Price | 把订单按时间均匀切片执行 | 无明显量能预期、追求简单基准 |
| VWAP | Volume-Weighted Average Price | 按历史成交量分布曲线切片，量大时段多成交 | 希望贴近全天平均成交价 |
| POV | Percentage of Volume（参与率） | 按实时市场成交量的固定比例参与，动态调整 | 跟随市场节奏，隐蔽性较好 |
| IS | Implementation Shortfall | Perold (1988)：纸面决策组合 vs 真实成交路径 | 看重决策时点、可承担时机风险 |

散户日频的缺口主要是隔夜跳空与涨跌停买不到，不是 TWAP 切片。见 `15-日频信号与次日执行.md`、`../04-风险管理/11-纸面账户与影子交易.md`。

## 3. 智能订单路由（SOR）与暗池

- 流动性分散在多个交易场所/渠道时，SOR 负责寻找最优执行路径  
- 暗池（Dark Pool）：不完全展示报价的场所，用于减少大单对公开市场的价格冲击（海外更成熟；国内主要为大宗交易等对应机制，具体以监管规则为准）  

## 4. 做市策略简述（了解即可，非零售参与领域）

- 做市商同时挂买卖双边报价，赚取买卖价差，核心风险是**库存风险**（单边行情下被迫持有不利头寸）  
- 经典学术框架：Avellaneda-Stoikov 模型，在报价宽度与库存偏离之间动态调整  
- 该领域对个人投资者基本不可参与，仅作为理解「盘口挂单行为」的背景知识（呼应 `../01-基础概念/07-市场盘口与交易微观结构.md`）  

## 5. 对散户/中小资金的实际启示

| 原则 | 说明 |
|------|------|
| 分批建仓/减仓 | 即使资金量不大，分批也能降低情绪化择时的影响 |
| 避免集合竞价情绪化下单 | 开盘瞬间流动性结构特殊，冲动单容易吃亏 |
| 理解「为什么大单会引发滑点」 | 有助于识别盘口异常（见大单小单场景） |
| 限价单优于市价单（多数场景） | 控制成交价格，避免极端滑点 |

## 6. 产品启示

- 若产品未来支持自动化调仓执行，应内置 TWAP/POV 式简单拆单，而非一次性市价下单  
- 教育内容中应说明「机构如何执行」，帮助用户理解盘口现象背后的合理解释（而非全部归因为「操纵」）
