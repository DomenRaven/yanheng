# 量化 MLOps 与模型生命周期管理

> 一句话：模型训练只是研究的起点，能不能在生产环境里被信任、被追溯、被及时叫停，才是决定"研究能不能变成产品"的关键——这是本知识库中工程属性最强的一篇。

## 1. 量化 MLOps 的三大支柱

```text
Feature Store（特征库） + Model Registry（模型注册中心） + Drift Monitor（漂移监控）
```

## 2. Feature Store（特征库/因子中间库）

### 核心能力：Point-in-Time 正确性

- 给定任意历史时间点，必须能返回"当时已知"的特征值，而不能混入未来才可得的信息（防止未来函数，呼应 `../01-基础概念/03-基本面分析.md` 中财报滞后披露的问题）  
- **强一致性承诺**：回测、模拟盘、实盘三个场景必须通过完全相同的 API、相同的特征版本获取数据，确保"研究结果可以无损转化为实盘"  

### 关键组件

| 组件 | 作用 |
|------|------|
| 因子/特征注册表 | 新特征上线前需登记定义、计算逻辑、负责人 |
| 数据血缘追踪 | 任意特征值可回溯到其依赖的原始数据表与计算代码版本 |
| 离线存储 + 在线存储 | 离线（训练用，分钟级更新）与在线（实盘推理用，毫秒/秒级）分层，保证效率与一致性平衡 |
| 特征质量监控 | 分布、缺失率、异常值的持续监控 |

## 3. Model Registry（模型注册中心）

- 追踪每个模型版本的：训练数据快照、超参数、评估指标、代码版本（commit hash）、训练时间  
- 支持"一键查询"：给定策略名，立刻看到当前生产版本、历史版本对比、性能演变曲线  
- 是**可审计性**的基础：出现异常时能快速定位"是哪个版本、哪次改动引入的问题"  

## 4. Drift Monitor（漂移监控）——防止"模型静默失效"

| 维度 | 检测指标 | 参考阈值区间（需按自身策略校准，非普适硬指标） |
|------|----------|----------------------------------------------|
| 数据漂移 | PSI（群体稳定性指标） | < 0.10 正常；0.10–0.25 中度漂移需关注；> 0.25 严重漂移，通常触发再训练评估 |
| 预测漂移 | IC（预测与实际收益相关性） | 相对自身历史基线的显著下降视为预警，具体数值因策略/市场而异 |
| 性能漂移 | 滚动夏普比率等风险调整收益 | 持续低于历史正常区间视为预警 |

### 分级响应机制（示意框架，供产品设计参考）

```text
预警级：IC/夏普轻微走弱 → 记录+观察，不动仓位
严重级：IC持续为负、PSI显著超标 → 降低该模型权重/仓位，启动诊断
紧急级：多指标同时恶化 → 暂停策略自动执行，转人工审核
```

**关键原则**：具体阈值必须基于自身策略的历史统计分布校准，不能照抄任何"通用阈值"直接上生产——不同策略的正常波动区间差异很大。

## 5. 模拟盘 / 影子交易（上线前最后一道关）

| 阶段 | 说明 |
|------|------|
| 历史回测 | 离线验证，速度快但环境理想化 |
| 模拟盘（Paper Trading） | 用实时行情跑策略但不真实下单，验证延迟、数据接入、执行逻辑的工程正确性 |
| 影子交易（Shadow Trading） | 在真实生产环境并行运行新策略/新版本，与现有策略同时接收行情但不实际下单，直接对比真实环境下的表现差异 |
| 小规模实盘灰度 | 小仓位真实资金验证，确认成本模型/滑点假设与实际相符 |

## 6. CI/CD for ML（工程流水线视角）

```text
数据校验 → 特征生成 → 模型训练 → 自动化评估（含质量门：IC/回测指标最低门槛）
    → 模型注册 → 模拟盘/影子交易 → 灰度实盘 → 全量上线 → 持续监控
```

- 质量门（Quality Gate）：新模型/新版本必须在既定指标上超过或至少不显著劣于当前生产版本，才允许进入下一阶段，避免"人工肉眼看着还行就上线"的随意性  

## 7. 产品启示

- MVP 阶段不需要重型 MLOps 基础设施，但**Point-in-Time 特征一致性**和**基本的漂移监控**应该从第一天就纳入设计，返工成本极高  
- 用户侧可展示的信任信号：模型版本号、最近一次评估时间、当前漂移状态（正常/观察/预警）——把工程可靠性转化为用户可感知的透明度  
- 严禁"重训练即上线"：任何模型更新都应先过模拟盘/影子交易，再灰度上线
