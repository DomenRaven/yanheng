# 日频信号与次日执行

> 一句话：收盘后的排序是信号，下一交易日才是执行；把两者当成同一时刻，就是回测里的收盘偷看，也是散户「今天看好明天涨停买不进」的来源。

## 1. 问题定义

设交易日 \(t\) 收盘后 scanner 给出信号，执行发生在下一交易日 \(t+1\)。

| 作弊/幻觉 | 正确处理 |
|-----------|----------|
| 用 \(t\) 收盘价在 \(t\) 成交 | 明确标注 cheat-on-close，不得当生产成交 |
| 忽略涨停/停牌 | 查 `limit_price` / `suspend_calendar` + 当日行情 |
| 用 \(t\) 信号在 \(t+1\) 仍按「一定能买到」 | 开盘涨停 → 不成交；待办作废或转 `watch` |
| 把择时模块验收成超额收益 | 只报告成交率、相对立即买入的成本差与局限 |

呼应 `05-回测与评估.md`「禁止收盘偷看」与 `08-执行算法与做市.md` 的 Implementation Shortfall：机构用 TWAP/VWAP 管大单冲击；**散户日频的缺口主要是隔夜跳空与涨跌停不可成交**，不是盘口切片。Perold 缺口的账户对应见 `../04-风险管理/11-纸面账户与影子交易.md`。

## 2. 默认成交假设（研衡 Phase 5）

对接文档默认：**次日开盘价**；涨跌停不可买。

理由（工程，不是「开盘在学术上最优」）：

- 与「收盘后出明日待办、次日开盘前后在券商下单」的作息一致。  
- 开盘价可得、可回测、可复现。  
- 必须在 UI 写清：这不是真实盘口撮合。

放弃「次日收盘近似」作为默认：会把整天的路径依赖藏进一个点，更像 cheat。可作为敏感性，不进主路径。

Jones, Shi, Zhang & Zhang 工作论文：小账户日度订单流呈 **动量**（买昨日涨、卖昨日跌），对次日收益负向预测；大账户偏逆向。这不是「开盘价假设的证据」，而是警告：把「追今日涨停明日继续」写进 `entry_rules` 会与最脆弱账户的亏损机制同向。

## 3. 失效（`invalid_if`）应可执行

空话：「模型下次排名大幅下降」（用户盘中无法核）。

可执行示例（实现时选少数、可回测的）：

- \(t+1\) 开盘涨停或停牌  
- 信号日后收盘跌破 N 日均线且放量（N 与回测同一套）  
- 排名跌出前 K（K 与建仓阈值一致，如 50 或 100）  

失效则待办作废，不得在模拟盘里「过期仍成交」。

## 4. 择时模块的诚实边界

三层证据方向一致，口径不同，禁止混用：

| 来源 | 口径 | 与「择时能赚钱」 |
|------|------|------------------|
| Odean (1999) | 买入随后 252 日收益低于卖出约 3.3%，且不够覆盖往返成本 | 散户换仓平均不是正期望 |
| Jones WP Table VIII | BLLO 跟踪组合：RT1–RT4 择时项为负；RT5 择时 −0.30% 不显著；机构 +0.19% | 即使跟随大户/机构净持仓，择时也几乎不贡献 |
| 张晓燕 2021 讲座 | 「择时几乎各组都赔」 | 口述，非原表 |

因此：

- `entry_rules.py` 的价值是 **把执行剧本写清楚**，降低追涨停与情绪化改价。  
- Walk-forward 报告：成交率；相对「\(t\) 收盘立刻买」的价差分布；涨停未成交占比。  
- **禁止** 用「加入择时后组合收益变好」作为上线唯一门禁——那会激励把评估口径改成看好的窗口。  
- 跟踪订单流的 alpha ≠ 用户账户 P&L（Jones 原文已声明）。scanner 排名可以当选股输入；不得在 UI 把截面预测写成「你昨天择时赚了」。

## 5. 产品启示

- UI 拆成「信号日结论」与「执行日待办」。  
- 待办最多 1–3 只（小资金 + 降过度交易；Barber & Odean 2000：换手本身抽净收益）。  
- 回测脚本与引擎共用纯函数，禁止页面里另写一套开盘价逻辑。  
- 成交失败要进拒绝日志（涨停/停牌），计入 IS 的机会成本，而不是静默跳过。
