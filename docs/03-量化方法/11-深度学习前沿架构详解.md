# 深度学习前沿架构详解（时序 + 关系建模）

> 一句话：架构选型应服务于数据特性和任务，不是越新越好——金融时序信噪比低，多数前沿架构在通用数据集上的漂亮指标很难原样复现到股票预测上，必须做场景化选型与严格的样本外检验。

## 1. 时序架构选型地图

```text
分钟级/订单簿/单标的方向性预测
└── 优先 TCN（因果卷积+扩张卷积+残差；小、快、可解释）

长序列（≥1024步）/多变量联合建模
└── PatchTST（切片成patch做注意力，抑制高频噪声）

强周期/趋势明显的数据（宏观利率、期限结构等）
└── N-BEATS / NHITS（堆叠全连接网络显式分解趋势与季节性；TimesNet 把序列折成2D做卷积）

需要融合多种异质输入（基本面+技术面+宏观+日历事件）+ 要求可解释性
└── TFT（Temporal Fusion Transformer）

有强周期性且需要长程依赖建模
└── Informer / Autoformer / FEDformer（稀疏/自相关注意力机制降低长序列计算复杂度）

跨变量相关性建模（把变量当Token而非时间步）
└── iTransformer（维度反转，适合多资产联合预测）

原版 Transformer
└── 慎用：除非序列短（≤256步）且样本量极大，否则金融数据上易过拟合
```

## 2. TFT（Temporal Fusion Transformer）架构拆解

TFT 是专为多时间跨度预测设计的混合架构，五个关键组件：

| 组件 | 作用 |
|------|------|
| 变量选择网络 VSN | 自动为不同特征分配重要性权重，天然具备特征筛选与可解释性 |
| 静态协变量编码器 | 处理不随时间变化的特征（如所属行业、市值分层） |
| LSTM 局部处理层 | 捕捉短期时序模式 |
| 可解释多头注意力 | 捕捉长程依赖，并输出注意力权重供人工解读 |
| 分位数回归输出头 | 输出预测分布而非单点，天然支持不确定性量化 |

**已知工程陷阱（需明确警示，非纸面宣传）**：

- 实证发现标准 TFT 在金融数据上训练早期可能出现**输出层梯度迅速塌陷**（编码器仍在学习但输出层学不动），导致预测缺乏多样性、方向准确率提升有限  
- 超参数敏感、训练不稳定是常见反馈，需要更保守的学习率调度、正则化与充分的样本外滚动验证，不能只看单次固定切分的结果  
- 适用前提：有多种异质输入 + 横截面（多资产）数据 + 需要概率预测 + 需要可解释性，否则性价比不一定优于更简单的模型  

## 3. GNN 关系建模详解

### 3.1 为什么用图

个股收益不是独立的：同行业、供应链上下游、股权关联、新闻共现等关系会传导价格影响（如某芯片龙头业绩超预期，上下游供应商/客户股价联动）。GNN 用于显式或隐式建模这种"关系溢出"。

### 3.2 主要变体

| 模型 | 核心机制 | 特点 |
|------|----------|------|
| GCN | 图卷积，聚合相邻节点特征 | 需要显式图结构，简单但表达力有限 |
| GraphSAGE | 可插拔聚合函数聚合邻居信息 | 支持归纳式（inductive）学习，可泛化到新节点 |
| GAT（图注意力网络） | 用注意力机制加权聚合邻居特征 | 权重取决于节点特征本身，泛化能力更强 |
| GATs_ts / 图时空网络 | LSTM（时序）+ GAT（关系）结合 | 兼顾个股时序特征与股票间关系，Qlib 已内置实现 |
| RSR（关系股票排序框架） | LSTM 时序嵌入 + 显式图关系 + 动态时间图卷积 | 需要显式定义关系类型（行业/供应链/概念） |
| TGC（时态图卷积） | 用图卷积校准时序嵌入 | 兼顾动量传导与关联结构 |

### 3.3 关系图的构建方式

| 关系类型 | 数据来源 |
|----------|----------|
| 同行业关联 | 行业分类标准（申万/中信等） |
| 供应链上下游 | 公司公告、产业链数据库 |
| 概念/题材共现 | 概念板块归属 |
| 新闻共现 | 舆情文本挖掘（见 `09-另类数据与情绪NLP.md`） |
| 股权关联 | 控股/参股关系 |

**GAT 的隐式建模优势**：不需要显式构建完整关系图，通过全局自注意力隐式学习节点间的影响权重，工程实现更简单，但可解释性弱于显式图。

### 3.4 实证参考（仅作方法论参考，非收益承诺）

公开研究中，GATs_ts 类模型在沪深300指数增强场景的历史回测中曾展示出相对基准的显著超额与更优信息比率，且引入新闻共现矩阵等显式关系后有进一步提升——但历史回测结果不代表未来表现，需在自有样本上重新验证。

## 4. 产品与工程启示

- MVP 阶段不需要追新架构：LightGBM/线性因子 + 简单时序特征通常性价比最高（见 `03-机器学习与深度学习.md`）  
- 若引入 TFT/GNN 等复杂架构，必须配套：Purged K-Fold/Walk-Forward 验证（见 `10-时序验证与标签工程.md`）、多随机种子集成压制方差、与传统因子做残差融合而非直接替换  
- 复杂架构的"可解释性输出"（如 TFT 的变量重要性、GAT 的注意力权重）应作为产品向用户展示"为什么给出这个信号"的素材来源
