# 强化学习与决策类方法

> 一句话：监督学习回答"未来会涨还是跌"，强化学习回答"现在应该做什么动作"——更贴近实际交易决策，但训练不稳定、奖励设计极易"作弊"，工程门槛高于监督学习。

## 1. 强化学习在交易中的基本框架

| 要素 | 交易场景映射 |
|------|--------------|
| 状态 State | 行情特征、持仓、账户净值、宏观指标 |
| 动作 Action | 买入/卖出/持有/调整仓位比例（离散或连续） |
| 奖励 Reward | 收益、风险调整收益（如夏普）、交易成本惩罚 |
| 策略 Policy | 状态到动作的映射，由神经网络参数化 |

## 2. 主流算法

| 算法 | 类型 | 特点 |
|------|------|------|
| DQN（Deep Q-Network） | 值函数方法，离散动作 | 经典入门，适合"买/卖/持有"离散决策 |
| PPO（Proximal Policy Optimization） | 策略梯度方法 | 用裁剪目标函数限制单步更新幅度，训练稳定性较好，是当前最常用的交易RL算法之一 |
| DDPG / SAC | Actor-Critic，连续动作 | 适合"仓位比例"这类连续控制问题 |
| Decision Transformer | 序列建模视角的离线RL | 把RL问题转化为条件序列生成（给定目标回报，生成动作序列），避开传统RL训练不稳定的痛点 |

## 3. 与 GNN 结合的架构模式（感知-决策一体化）

```text
市场数据（行情/基本面/舆情/关系图）
        ↓
GNN/GAT 编码器（学习股票关系与上下文嵌入）
        ↓
策略网络（PPO/DQN 等，接收嵌入向量）
        ↓
输出：动作（买/卖/持有/权重调整）+（可选）可解释性理由标签
        ↓
市场环境反馈 → 策略梯度更新
```

- 双头输出设计（动作头 + 解释头）是提升可解释性的常见工程手段：解释头输出"归因类别"（如技术信号/行业趋势/政策/情绪/估值异动），便于向用户呈现决策依据  

## 4. 奖励设计的核心陷阱

| 陷阱 | 说明 |
|------|------|
| 奖励作弊（Reward Hacking） | 模型找到能拿高奖励但不符合真实交易目标的"漏洞"策略（如频繁小额套利吃掉理论价差却忽略真实滑点） |
| 忽略交易成本 | 奖励函数不含手续费/冲击成本，训练出的策略实盘大幅衰减 |
| 忽略风险 | 只优化累计收益而不惩罚回撤/波动，容易学出高杠杆赌博式策略 |
| 非平稳环境 | 市场状态转移规律本身随时间变化，历史训练的最优策略未必适应新环境 |

**建议**：奖励函数应显式包含风险调整项（如收益 − λ×波动 或直接用夏普类指标的差分），并在训练环境中加入真实的交易成本、涨跌停、T+1 约束。

## 5. 离线强化学习与仿真环境

- A股实盘试错成本高，通常先在历史数据构建的仿真环境中训练（离线RL）  
- 仿真环境的真实性至关重要：需要包含冲击成本模型、涨跌停/停牌约束、T+1限制，否则训练出的策略是"作弊环境"下的产物（呼应 `03-量化方法/08-执行算法与做市.md` 与 `05-回测与评估.md` 的真实性要素）  
- 生成式方法（见 `13-生成式与Agent前沿.md` 中的扩散模型市场模拟）可用于生成更真实、可控的仿真市场环境，弥补历史数据样本有限的问题  

## 6. 产品与工程启示

- RL 类策略门槛高、可解释性差、训练不稳定，**不建议作为面向普通用户的首发功能**，更适合作为高级研究模块或组合再平衡的辅助引擎  
- 若上线RL驱动的建议，必须提供"决策理由"展示（呼应双头输出设计），避免纯黑盒建议  
- 任何RL策略上线前必须过 Walk-Forward + 真实成本仿真的双重检验
