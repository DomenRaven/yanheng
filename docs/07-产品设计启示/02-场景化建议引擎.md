# 场景化建议引擎（设计规格草案）

> 一句话：建议引擎是规则+模型的编排器，输出必须可审计、可回放、可拒绝。

## 1. 状态机（账户 × 标的）

账户级状态示例：`空仓观察 | 建仓中 | 持有 | 加仓评估 | 减仓评估 | 风控熔断 | 冷静期`

标的级状态示例：`未持有 | 持有盈利 | 持有亏损 | 接近涨停/跌停 | 停牌 | 事件临近`

转移由：信号变化、风控触发、用户确认、时间失效 驱动。

## 2. 建议卡片 Schema（建议）

```yaml
advice_id: uuid
as_of: timestamp
symbol: "600000.SH"
action: reduce   # watch|open|add|reduce|close|stop_loss|take_profit|rebalance
size_pct_nav: [0.02, 0.05]
horizon_days: [5, 20]
confidence: 0.46   # 校准后概率或分位，需定义
reasons:
  - type: factor
    ref: MOM-12-1
    detail: "动量因子处于截面高位但衰减加速"
  - type: risk
    ref: concentration
    detail: "单票已占净值 18%，超过用户上限 15%"
risks:
  - "若市场转入高波动区制，建议失效"
invalid_if:
  - "收盘跌破 20 日均线且成交量放大"
  - "组合 CVaR 超限"
constraints_applied:
  - Tplus1
  - max_single_name
disclaimer: "仅供研究辅助，不构成投资建议"
```

## 3. 决策伪代码（概念）

```text
signals = collect(symbol)
risk_ok = check_limits(account, candidate_trade)
tradable = check_auction_limits(symbol)
if not tradable or not risk_ok:
    return watch_or_reduce(reasons=...)
if conflict(signals) > threshold:
    return watch(confidence_low=True)
target = optimize(account, signals)
delta = target - current
return map_delta_to_advice(delta)
```

## 4. UX 原则

- 默认展示「为什么」折叠详情  
- 冲突用对比视图，不偷偷平均  
- 一键采纳前强制显示风险与失效条件  
- 保留用户覆盖理由（用于行为分析）
