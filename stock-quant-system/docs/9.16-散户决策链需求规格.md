## 3. 证据收敛：散户真正在要什么

散户口头常说「推荐一只能涨的」。账户数据和理论库都指向另一件事：**预测只是信号；亏钱发生在仓位、时机、费用、集中度和卖出纪律上。**

### 3.1 亏损结构（A 股大样本）

某主要交易所 2016–2019 账户（Jones 等工作论文 **英文原文**，见 `../../docs/02-经典理论/07-散户投资者实证.md`）：

- 活跃散户 **5,340 万** 户；RT1（<10 万）占账户 **58.7%**。研衡 1 万 / 10 万落在 RT1。  
- 成交额：散户 **81%**、机构 17%、公司 2%；持仓：散户 **22%**、机构 17%、公司 62%。散户日换手约持仓的 10%。RT3（50–300 万）成交占全市场约 27%，最活跃。  
- BLLO 跟踪组合（\(n=140\)，**不是**账户已实现盈亏）：RT1–RT4 年化 ROI −5.61% 至 −2.80%；RT5 −0.29%（选股 +1.05% 被费用 −1.03% 与不显著择时吃掉）；机构 +1.15%。  
- 小账户订单流负向预测次日收益、呈日度动量；张晓燕讲座口述：跟随微型账户约 **−20bp/日**。  
- **择时**在 RT1–RT4 为负、RT5 不显著；讲座亦称「几乎各组都赔」。  
- 媒体常引的「<10 万亏 20.53% / 户均 2457 元」：**论文英文与讲座 HTML 均未核到原表**，本规格不再当作论文结果。

对研衡的含义：

1. 用户资金量级（练习 10 万 / 实操 1 万）落在 **亏损最重的小账户带**，产品必须按小资金约束设计，不能按机构组合的 30–40 只持股来抄。  
2. 只加强选股排序 **不够**：必须把「买多少 + 明天能否成交 + 费用」做成一等公民。  
3. Phase 5 的择时模块 **禁止** 验收成「择时能赚钱」；验收应是 **可执行、可作废、相对「信号日收盘立刻买」的成本差（含局限）**。

### 3.2 行为：不是缺信息，是缺护栏

| 行为 | 证据 | 产品应对（理论库已有对应） |
|------|------|----------------------------|
| 过度交易 | Barber/Odean；理性指数「过度交易」；深交所 2020：盈利者短线行为更低 | 「观望」一等动作；明日待办上限 1–3 只 |
| 处置效应 | 理性指数；深交所 2020：盈利者处置效应更低 | 计划止损优先于成本价；禁止「仅因浮亏」加仓 |
| 分散不足 | 理性指数把 under-diversification 列为四维之一（报告未核「1.6 只」）；Sui–Wang 真钱样本均持股 2.96 vs 模拟 4.36；社区爆仓几乎都是满仓单票+杠杆 | 单票 ≤15%、同时 2–3 只、现金缓冲 ≥10% |
| 追涨杀跌 / 炒小炒差 | 张晓燕：中小户追涨杀跌；理性指数第四类 | 涨停不可买；行为冲突提示；ST 由策略层决定 |
| 无退出计划 | Reddit / 国内社区高频 | `invalid_if` + 参考止损/止盈价必须可执行 |
| 仓位拍脑袋 | Reddit「第一年最大错误是仓位」；东财/投顾文「以损定仓」 | 股数由净值、手数、止损距离反推，不是「自己把控」 |
| 先模拟再实盘 | 知乎选软件帖、QMT/PTrade 教程、Reddit paper trade | 本机 paper 账户；与券商模拟盘不同，必须自带 A 股约束 |

### 3.3 理论库已经写过、且与证据同向的产品原则

来自 `docs/00-总览/01-任务理解与缺口分析.md`、`04-风险管理/03`、`02-经典理论/05`、`04-风险管理/02`、`07-产品设计启示/01–03`、`06-竞品与行业/03`：

- 建议 = f(市场状态, 标的信号, **账户状态**, 约束, 用户偏好)  
- 输出必须带：动作、仓位区间、持有期、置信度、理由、风险、**失效条件**  
- 优先级：合规可交易 > 生存风控 > 账户结构 > 信号 > 收益增强  
- 仓位决定生死；每条建议带 **建议仓位** 与 **最大可承受亏损金额**  
- 不要做成又一个行情 App；做「懂账户状态的可解释副驾」  
- 观望是一等动作，用来降低过度交易

这些原则 **Phase 4 部分落地**（优先级、卡片、集中度、行为冲突）。**Phase 5 Must（2026-09-17 自查）已补齐可执行股数、本机模拟、明日待办与建议落盘**；Should S1/S2/S9 见 §5.2（2026-09-18 补）。

### 3.4 竞品已经给了、研衡不该去拼的

同花顺/东财：行情与资讯完整性。雪球：社区。聚宽/米筐：研究平台。QMT/PTrade：合规程序化到柜台。

散户在知乎上真正追问的「软件缺口」往往是：**仓位按钮、模拟盘、条件单、回测假设**。研衡的切口不是闪电下单，而是 **账户状态机 + 可解释建议 + 本机纸面账户（含 T+1/涨跌停/费用）**。

## 4. 目标用户与 Jobs-to-be-Done

### 4.1 本产品主用户（已拍板）

| 项 | 定义 |
|----|------|
| 画像 | 进阶个人：会用本机工具、接受日频、不要求秒级 |
| 资金 | 练习默认 10 万；年底实操预设 **1 万闲钱** |
| 执行 | 用户在券商 App 手动下单；系统只给待办与模拟 |
| 周期 | 日频（信号日收盘 → 执行日下一交易日） |
| 成功 | 能连续跑通工作流、少做无计划交易、复盘看得到偏差；**不以收益率作为唯一 KPI**（产品定位文档第 6 节） |

### 4.2 八个工作（按对小账户伤害排序）

1. **选得出少数可研究标的**（不是全市场噪音）  
2. **算得出买多少股、花多少钱、占净值多少、最多亏多少**  
3. **知道明天怎么买、买不进怎么办、什么条件作废**  
4. **知道持仓该不该卖/减/止盈止损，以及卖多少股**  
5. **先在纸面账户上把规则跑顺，再决定是否用真钱**  
6. **少做冲动交易**（频率、满仓、浮亏加仓）  
7. **能解释「为什么」并核对建议后来发生了什么**  
8. **遵守 A 股硬约束**（T+1、100 股、涨跌停、停牌、费用）

工作 2–5、8 在 Phase 5 Must 自查中 **已落地**（股数/模拟/待办/T+1 等）；工作 1、6、7 的 Should（S1 理由包、S2 行业上限、S9 计划 vs 实际）见 §5.2。

### 6.2 建议引擎动作空间（代码事实）

Schema 注释允许 `watch|open|add|reduce|close|stop_loss|take_profit|rebalance`。

实际产出：

- 观察名单：`watch` / `open`  
- 持仓：`watch` / `stop_loss` / `reduce` / `take_profit` / `hold`，再平衡覆盖层可把 `hold` → `rebalance`  
- **从未产出 `add`、`close`**（平仓是页面按钮写 `positions.is_closed`，不是建议动作）

这不是 bug。结合证据，**浮亏加仓是高伤害路径**，本轮 Must 是「禁止因浮亏加仓」。若 Phase B 要支持 `add`，仅允许：趋势与排名仍支持 **且** 未破单票/现金约束 **且** 不是为了摊薄成本。

## 7. 目标工作流（用户侧，微调后）

```text
收盘后
  确认数据更新完成（或增量）
  → 周末可选 retrain_schedule（冠军门禁含组合收益，不只 RankIC）
  → scanner（只读 champion）
  → 生成：明日待办（≤3）+ 建仓/调仓计划（股数、金额、最大亏损）
次日
  涨停/停牌 → 待办作废或转为 watch
  否则：点「模拟成交」 或 在券商按待办手动下单后「确认成交」
收盘后
  持仓建议（卖/减/止盈止损 + 股数）
周末
  漂移监控 + 模拟盘周报（阶段 D）
```

**1 万元默认约束**（可 `config.yaml`）：最大同时持仓 2–3 只；单票 ≤15% 净值；现金缓冲 ≥10%；买入默认 **次日开盘价**（涨跌停不可买）；滑点为简化假设，UI 必须标明非真实盘口。

## 10. 测试与诚实边界

- 任何「规则有效」必须有 DuckDB 查询或回测数字。  
- 模拟净值 **不是** 实盘收益；文案禁止混用。  
- 冠军替换仍走同一套 Walk-Forward，且含 Top-N 组合收益。  
- 本需求文档的社区部分是定性，**不能**当回测显著性使用。

已知上限：

1. 无 Level-2，滑点只能是规则假设。  
2. 小账户 15% 单票上限与「1% 账户风险」可能冲突：高价股 1 手就超过 1 万账户的风险预算 → 正确行为是 **不买 / watch**，不是拆碎股。  
3. 公开信息有价值（张晓燕），但本系统不做全自动舆情交易。  
4. 灌库未完成时，scanner/建议质量受数据截止约束，必须展示截止时间。
