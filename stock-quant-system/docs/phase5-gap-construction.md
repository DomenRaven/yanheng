## 1. M16 建议→成交→复盘

### 1.1 规格原文

> 至少一条 advice_id 全链路。

现状：`paper_trades.advice_id` 与复盘页 JOIN 已有；**无自动化证明 persist→成交→查询是同一条路径**。

### 1.2 理论依据（先读后写）

| 来源 | 用什么 | 不用什么 |
|------|--------|----------|
| `07-产品设计启示/02-场景化建议引擎.md` | 「输出必须可审计、可回放」；`advice_id` 快照 | 把涨跌幅当「照做能赚多少」 |
| `07-产品设计启示/04-散户工作流与纸面账户.md` | T 日建议 → T+1 模拟或确认 → 周末复盘 | 系统下单 |
| `04-风险管理/11-纸面账户与影子交易.md` §2 | Perold (1988) **Implementation Shortfall**：决策纸面组合 vs 真实成交路径 | 机构 TWAP 切片（散户日频不是这个） |
| `03-量化方法/15-日频信号与次日执行.md` | 日频缺口 = 隔夜跳空 + 涨跌停未成交；相对「信号日收盘立刻买」的价差 | 「择时能赚钱」 |
| `02-经典理论/05-交易心理学专论.md` | 交易日志：计划 vs 情绪/执行；确认偏误靠留下当时 reasons | 只展示后来涨了就当建议对 |

数学模型（日频简化，不是完整 Perold 分解）：

\[
\text{fill\_vs\_close} = \frac{P_{\text{fill}}}{P_{t,\text{close}}} - 1
\]

未成交记拒绝原因，禁止用收盘价补假成交（`11-纸面账户` §2 产品验收）。

### 1.3 实现方法（ADR）

- **选**：`advice/advice_trace.py` 纯查询（页面只调用）；临时库 `persist_advice_cards` → `execute_paper_order` → JOIN 出完整行。  
- **弃**：要求生产库已有用户成交才算 M16 通过（灌库暂停且无成交则永远卡死）；复盘页再写一套 SQL。  
- 复用：已有 `advice_log` / `paper_trades` / `persist_advice_cards` / broker 幂等。

### 1.4 验收数字

临时库：**恰好 1 条** `advice_id` 同时有建议行与 `reject_reason IS NULL` 的成交；`fill_shares == size_shares`；`fill_vs_advice_close` 可计算。生产库 trace 条数如实展示，零条不假装「用户已跑通」。

## 2. S1 Top-N 理由包

### 2.1 规格原文

> Top-N 理由包（因子 + 行为冲突 + 一句话）。扫描表有 ROE/动量/冲突；缺结构化理由包与行业暴露。

### 2.2 理论依据

| 来源 | 用什么 |
|------|--------|
| `07/02` Schema | `reasons[]` 带 `type`/`ref`/`detail`；冲突不偷偷平均 |
| `04-风险管理/03-场景化决策建议框架.md` | 建议 = f(市场, 标的, 账户, 约束, 偏好)；reasons 可追溯；信号冲突 → 展示冲突、降置信或观望 |
| `02-经典理论/05-交易心理学专论.md` | **确认偏误**：强制列出反方证据（行为冲突），不能只堆多头因子 |
| `02-经典理论/01-有效市场与行为金融.md` + scanner 现设计 | 行为信号是交叉验证，**不改模型排名**（Phase 2 原意） |
| `03-量化方法/01-多因子与Barra.md` | 卡片展示主要暴露与风险来源；MVP 精简风格 + 少量 Alpha |

一句话（`plain_summary`）服务工作 7「能解释为什么」；因子/冲突服务可审计，二者分层（已有引擎注释）。

### 2.3 实现方法（ADR）

- **选**：抽出 `build_reason_pack(row)`：`factors[]` + `conflicts[]` + `one_liner`；扫描表与卡片共用。  
- **弃**：LLM 现编理由（Won’t：黑盒当指令；也破坏可回放）。  
- 行业名放进理由包的 `exposure` 字段（与 S2 数据同源），不在本步做中性化。

## 3. S2 行业暴露 / 过滤

### 3.1 规格原文

> 可选行业暴露/轮动过滤。`industry_classification` 已入库；优化器无行业中性。

### 3.2 理论依据

| 来源 | 用什么 |
|------|--------|
| `03-量化方法/01-多因子与Barra.md` | \(r_j=\sum_k X_{jk}f_k+e_j\)；行业是共同因子；优化约束「行业偏离上限」 |
| `03-量化方法/04-组合优化.md` §2 | 产品默认约束应含行业偏离；散户通常多头现金账户 |
| `04-风险管理/02-仓位与资金管理.md` | 组合硬限制含 **单行业上限**；相关持仓合并计量 |
| `01-基础概念/05-产业面与行业分析.md` | 中观景气 ≠ 把同行业 3 只当分散；热度高但景气未兑现 → 交易属性 |
| `02-经典理论/07` + Sui–Wang | 真钱更不分散（持股 2.96 vs 模拟 4.36）；1 万账户 2–3 只时，**同行两只 ≈ 单票集中** |
| 规格 C3 | 「行业/风格完全中性化的机构优化器」是 Could，保持局限 |

### 3.3 实现方法（ADR）

- **选**：小账户启发式——明日待办 / 开仓候选 **同一 `industry_code` 最多 1 只**（按模型排名取先到先得）。这是风险预算的离散版，不是 CNE5。  
- **弃**：在优化器里上完整行业中性二次规划（C3；样本 2–3 只时约束会无解或假中性）。  
- 复用：`industry_classification` ASOF（与 `panel.py` 同口径：`start_date <= as_of` 最新一条）。查询放 `advice/`，不让页面写 SQL。

## 4. S9 计划仓位 vs 实际仓位

### 4.1 规格原文

> 计划仓位 vs 实际仓位记录。理论库行为纠正；可随 paper_trades 自然出现。

### 4.2 理论依据

| 来源 | 用什么 |
|------|--------|
| `04-风险管理/02-仓位与资金管理.md` §5 | **「记录计划仓位 vs 实际仓位帮助行为纠正」**——规格 S9 的直接出处 |
| `02-经典理论/05-交易心理学专论.md` | 过度自信 → 过大仓位；计划止损优先于成本；事后对照计划 |
| Perold IS（`04/11`） | 未成交 / 成交股数不足 = 机会成本，应看见，而不是当系统没建议 |
| Odean / Barber 过度交易 | 实际仓位 **大于** 计划（加码）与 **小于** 计划（不敢买）都是偏差，台账要两侧 |

### 4.3 实现方法（ADR）

- **选**：在 M16 trace 上增加 `planned_shares` / `fill_shares` / `shares_gap`；复盘页一张表。不新建表（规格说可随 paper_trades 自然出现）。  
- **弃**：单独 `position_plan_ledger` 表（冗余，违反复用存量）。

## 6. 再核对浅实现（2026-09-18 第二圈）

### 6.1 M8 空话失效条件

- **理论**：场景建议 Schema 要求 `invalid_if` 可执行；交易心理学「无退出计划」；不能用无法盘中核对的「排名大幅下降」。
- **ADR**：watch/hold 用可核对列表；open 无止损价则无法以损定仓 → watch（对齐 M5/M7）。
- **弃**：继续只给 open 写失效条件。

### 6.2 M1 静默读最新文件夹

- **理论**：CD4ML 冠军-挑战者；闸门「不显著不得替换」。静默加载最新 run 等于绕过晋升。
- **ADR**：缺 `champion.json` 失败。
- **弃**：Phase1 兼容回退。

### 6.3 探针口径

- 生产未就绪 = DATA_BLOCKED，不与 Must 代码失败混退出码。
- 完整 trace = `complete_trace_count`（有成交），不是 `advice_log` 行数。
