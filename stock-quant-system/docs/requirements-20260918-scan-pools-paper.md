## 1. 理论对齐与优化原则（闸门 1.5 摘要）

| 主题 | 理论要点 | 对需求的优化（相对用户原话） |
|------|----------|------------------------------|
| 分池训练 | Barra：控制不想要的 Size/交易所暴露；微盘与主板流动性、财务覆盖、涨跌停幅度不同，混训易变成「小盘风格机」 | **采纳分池**；池定义为 `pool_hs`（沪+深）与 `pool_bj`（北交所；CDR `689009` 归 **hs 科创** 或单独标注，默认跟代码交易所，不进 bj 池） |
| 冠军门禁 | CD4ML：同协议 Walk-Forward + **Top-N 组合收益** 才能换冠军；禁止只比 RankIC | 每池独立 `champion`；晋升日志带 `pool_id`；UI 禁止混读另一池模型 |
| 扫描存档 | 漂移监控与「建议可追溯」已要求 `prediction_log`；缺的是 **run 元数据 + 跨次坚持度** | 复用/扩展 `prediction_log`，新增 `scan_run`；去重键 = `(pool_id, asof_trade_date, model_run_id)` |
| 「一直在前 50」 | 不是预测胜率；是 **横截面排名稳定性**（拥挤/风格漂移观察） | 指标名用「前 50 坚持度」，UI 标明 **非荐股、非胜率** |
| 日更范围 | 决策频率=数据频率；全市场日 K 对「持仓决策」过重；`limit_price`/`daily_basic` 本就是一日一张全市场表 | **日更砍全市场 quotes**，改为持仓+待办增量；**保留**全日 `tushare_market_data`；**周更**才全市场 quotes + 财务/行为 + **双池扫描/重训** |
| 纸面账户 | Perold IS：未成交必须显式；信号日 ≠ 执行日；缺次日开盘价时 **不得伪装成已拒绝成交** | 一键练习默认只模拟 **明日待办 ≤3**；缺 `exec_date` 开盘价 → **`pending`（待开盘）**，不计「拒绝」；拒绝原因必须上屏 |

**已知不确定（第 7 条）**：

- 分池后样本外是否仍显著：必须以双池各自 Walk-Forward 为准，**不预设**「分池一定涨 IC」。  
- 「坚持度」与未来收益的相关：本轮只做可观测榜单，**不**把坚持度写成 alpha 因子除非另开验收。  
- 持仓日更 quotes 在持仓为空时：仅跑 universe + `tushare_market_data`（+ 可选待办符号），不空跑全市场。

## 2. R1 — 掘金扫描存档与榜单

### 2.1 目标

1. 每次用模型做掘金扫描，落 **可复现存档**。  
2. 相同 **`(pool_id, asof_trade_date, model_run_id)`** 不重复插入（幂等）；若强制重扫，更新 `scanned_at` 与分数/名次，不新增平行 run。  
3. 每支股票每次扫描的 **名次** 可查。  
4. **AI 解释页**：选股票后可见历史名次序列（表 + 简图）。  
5. **掘金扫描页** 新页签「榜单 / 走势」：  
   - 某次扫描 Top-N  
   - 单票名次走势  
   - **坚持榜**：最近 \(N\) 次有效扫描中，进入前 50 的次数 / 占比（默认 \(N=5\) 或「最近 20 个交易日有扫描的次数」）

### 2.2 数据（建议）

| 表 | 作用 |
|----|------|
| `scan_run` | `run_id`, `pool_id`, `asof_trade_date`, `model_run_id`, `universe_size`, `scanned_at`, `source`（ui/cli/weekend） |
| `prediction_log`（扩展） | 现有 PK 增加或并列 `pool_id`；保留 `rank`/`pred_score`/`is_tradable` |

去重：插入前查 `scan_run`；已存在则跳过全表重写或仅 upsert 分数（实现时二选一写进验收报告，默认 **upsert 同键**）。

### 2.3 验收数字

| 条款 | 标准 |
|------|------|
| R1.1 | 连续两次同池同 asof 同冠军 `run_scan`，`scan_run` 行数 +0，`prediction_log` 行数不倍增 |
| R1.2 | 任意 Top50 股票在 AI 页能查出 ≥1 条历史名次（有存档后） |
| R1.3 | 「坚持榜」可列出「最近有效扫描中前 50 命中次数 ≥K」的股票（默认 K= 有效次数，即 **全程都在前 50**）；空库时明示「存档不足」而非空白死页 |

## 3. R2 — 北交所 / 沪深分池与双冠军

### 3.1 池定义

| `pool_id` | 成分 | 冠军指针 |
|-----------|------|----------|
| `hs` | `universe.exchange IN ('sh','sz')` 且未退市 | `mlops/registry/champion_hs.json`（或 `champions.json` 内字段） |
| `bj` | `universe.exchange = 'bj'` 且未退市 | `mlops/registry/champion_bj.json` |

- 扫描：`run_scan(pool_id=...)` **只加载该池冠军**，只对该池截面打分。  
- UI：掘金页默认分 Tab「沪深池 / 北交所池」；首页/建议引擎对观察名单 **分池取 Top**，再合并进观察（合并规则见下）。  
- 训练：周末流水线分别训练/评估；晋升 **互不覆盖**。  
- 兼容：迁移期可读旧 `champion.json` → 视为 `hs` 初始，直至 `bj` 首训完成；`bj` 未就绪时北交所 Tab 明示「无 bj 冠军」，**禁止**用 hs 模型给 bj 打分。

### 3.2 合并进「明日待办 / 一键练习」的优化规则（理论优化）

用户要分池，但不等于待办里塞满北交所。建议默认：

- 明日待办最多 3 条：**优先 `hs` 池 open 候选**；仅当用户在设置中打开「允许北交所开仓」时，才按名次插入 bj（仍受单票 15%、现金 10%、同时 2–3 只约束）。  
- 掘金坚持榜 / Top 表：**分池展示**，不做跨池混排（避免再次出现「全市场 Top50≈北交所」的误导）。

### 3.3 验收数字

| 条款 | 标准 |
|------|------|
| R2.1 | `hs` 扫描结果 0 条 `exchange=bj`；`bj` 扫描 0 条非 bj |
| R2.2 | 缺少对应 champion 文件时该池扫描失败并可读错误，不静默用另一池 |
| R2.3 | 双池各有独立 Walk-Forward 记录（可先 bj 用较小历史；样本不足须在报告写「局限」）后方可声称「bj 冠军已晋升」 |

## 5. R4 — 模拟成交可读、可成功路径

### 5.1 对你截图的诊断（基于代码，非臆测）

图：`成交 0 · 跳过 0 · 拒绝 29`，净值 1 万不变；建议日 `2026-09-17`。

代码路径：`一键练习` → `run_practice_cycle` → 对 **几乎全部** `open/reduce/...` 且 `size_shares≥100` 的卡片调用 `simulate_advice_cards`；成交价口径是 **`exec_date`（次日）开盘价**。

关键缺陷：

1. **缺次日开盘价时直接 `rejected`「缺少开盘价」**，且该分支 **不写** `paper_trades` → 库内查不到拒绝原因，UI 又只显示总数 → 「没做成」且「看不懂」。  
2. 一键练习模拟 **观察名单里大批 open（阈值前 50）**，与规格「待办最多 1–3」「1 万同时 2–3 只」冲突；1 万账户即使有价，也会连环「现金不足」。  
3. 成功标准被理解成「净值必须变」；按理论，**涨停/缺价/现金不足拒绝是正确行为**，但必须解释清楚。

（图中「掘金全量筛选 (共 0 只)」若来自同页其它区块，施工时一并核对文案；可能与筛选漏斗/空观察有关，列入 R4.5 文案审计。）

### 5.2 优化需求

| ID | 需求 |
|----|------|
| R4.1 | **一键练习默认只模拟 `tomorrow_todos`（≤3）**；全量卡片模拟改为二次确认的高级选项 |
| R4.2 | 若 `exec_date` 尚无开盘价：状态 **`pending`（待开盘后再练）**，计入「待执行」而非「拒绝」；净值旁文案：「信号已生成，执行日开盘后可点『按待办模拟』」 |
| R4.3 | 结果区展示 **原因汇总表**（缺少开盘价 / 现金不足 / 涨停 / T+1 / 幂等跳过 …）+ 可展开明细 |
| R4.4 | 提供「执行日已开盘」一键：只对待办里仍有效的卡片模拟；至少一条 **可成交路径** 的测例（临时库造开盘价）净值或持仓变化可断言 |
| R4.5 | 文案：练习 ≠ 荐股赚钱；拒绝/待执行是 A 股约束，不是按钮坏了 |

### 5.3 验收

| 条款 | 标准 |
|------|------|
| R4.a | 无次日开盘价时：`rejected` 不因「缺开盘价」≥1；应为 `pending` 或跳过待执行 |
| R4.b | 有次日开盘价 + 现金足够 + 非涨停：待办内至少 1 笔 `filled`，净值或 `paper_positions` 变化 |
| R4.c | UI 可见拒绝/待执行原因 Top 分布，无需查库 |
