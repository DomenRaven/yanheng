# Phase 3 验收报告 —— 深度学习挑战者（行业图注意力模型）

验收时间：2026-08-26。方法：全部数字来自真实训练/真实回测/真实统计检验，不是示例或估算数字。
对照 `.cursor/rules/quant-dev-loop.mdc` 记录的CD4ML冠军-挑战者门禁：
"挑战者要用同一套验证协议跑出样本外指标，且显著优于当前冠军才能替换或融合；不显著则保留基线为
生产模型，如实记录对比结果——包括'新模型没有更好'这种结论"。

## 1. 技术选型依据

- **架构**：行业关系图注意力网络（简化GAT），不是TFT/PatchTST。理由见
  `docs/03-量化方法/11-深度学习前沿架构详解.md` 选型地图：本项目特征面板是月度截面
  （127个截面日），不是长序列，TFT/PatchTST面向"长序列+多变量联合建模"在此场景性价比低，
  且文档明确警示TFT训练早期梯度塌陷的已知陷阱；GNN天然契合"截面+关系图"数据形态。
- **关系图构造**：复用 `research/panel.py` 已point-in-time对齐的申万行业分类
  (`industry_code`，覆盖99.2%截面行)构建"同行业"边，不新增数据源。
- **工程实现**：未引入 `torch_geometric`（额外CUDA版本对齐/编译复杂度，在当前规模下投入
  产出比不划算），改用块对角注意力掩码 + `F.scaled_dot_product_attention` 做一次批量带掩码
  多头自注意力，数学上等价于对每个行业子图分别做全连接图注意力。**如实说明**：这是自实现的
  简化图注意力机制，不是标准GAT/GraphSAGE库的直接调用。
- **验证协议**：与 `research/train_lightgbm.py` 完全相同的 `_date_level_splits`
  (walk_forward, expanding)、完全相同的三重障碍标签(`attach_triple_barrier_labels`)、
  完全相同的样本外评估函数(`evaluate_fold`, Spearman RankIC) —— 严格同协议对比。

## 2. 训练实测

- 硬件：NVIDIA GeForce RTX 4060 Laptop GPU，显存8188MiB（`nvidia-smi`实测，2026-08-26）。
- 训练命令：`python -m research.train_dl --epochs 15`，数据来源
  `data/feature_panel.parquet`（127个截面日，501,703行，13个因子特征）。
- 实测耗时：约41分钟（14:23:46 ~ 15:04:36），显存峰值约6.4GB（单日截面最多约5300节点，
  多头注意力分数矩阵峰值显存<1GB，远低于硬件上限，无需邻居采样降规模）。
- 产出：`mlops/registry/20260826_150436_dl/`（`model_dl.pt` + `model.pkl` + `metadata.json`）。

## 5. 如实记录的矛盾发现（对齐vibe coding八荣八耻第7条"坦诚存疑"）

这是本轮评估里最重要、也最容易被忽略的一点：**DL在全市场排序能力(RankIC)上统计显著更好，
但代入实际会被使用的Top-30组合策略后，收益反而不如LightGBM冠军**（虽然这个反向差异本身
未达统计显著）。可能的原因（推测，未逐一验证，如实标注为待验证假设）：

1. RankIC是对**全市场所有股票**排序质量的度量，Top-30回测只关心**排名最靠前的30只**——
   DL可能在中低分段排序更准，但在最高分段（真正决定Top-30选股的区域）与LightGBM相比
   没有优势甚至更弱，两个指标衡量的不是同一件事。
2. 行业注意力掩码可能让模型在同行业内部"抹平"了个股差异（block-diagonal attention
   本质是行业内信息聚合），这对全市场排序的稳健性有帮助，但可能削弱了识别"同行业内哪只
   最强"这种Top-N选股最需要的能力。
3. 训练用pairwise ranking loss覆盖全市场所有相关性对，没有对Top分位区域加权，损失函数
   本身没有针对"Top-30精度"做优化。

**结论：不满足冠军-挑战者门禁的替换条件**（"显著优于当前冠军才能替换"——本次是"一个指标
显著更好，但更贴近实际使用场景的指标反而更差"，不构成"显著更好"），**维持LightGBM
(`20260826_123439`)为生产冠军**，决策已写入 `mlops/registry/promotion_log.jsonl`
（`promoted: false`，含完整数字和理由）。DL模型文件保留在registry中留痕，不删除。

## 7. 局限与后续可能方向（不在本轮范围内，仅记录）

- 未尝试对pairwise ranking loss按分位数加权（增大Top分位样本权重）——如果未来要继续
  打磨DL挑战者，这是最值得先试的方向，而不是加深/加宽网络。
- 未做超参数搜索（hidden_dim/n_heads/lr等全部用默认值一次性跑通）——当前结论足以支撑
  "不替换冠军"的决策，投入超参搜索前应先确认方向（如上一条）有没有希望，避免无意义的
  算力消耗。
- `industry_code` 覆盖率99.2%，未覆盖的0.8%行业未知的股票在掩码里退化为仅自环
  （见 `research/train_dl.py::_build_industry_mask`），对结果影响未单独量化。
